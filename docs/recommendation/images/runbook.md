# Private H&M image pipeline runbook

The `qukiuthin` Kaggle CLI credential was refreshed on 2026-11-06. A competition file listing and selective image requests now work. Keep `data/hm/` private and avoid public hosting. The import commands below target only the isolated `recommendation_test` DB, not the main `commerce` DB.

1. Prepare requests: `python scripts/hm/build-image-manifest.py`.
2. Pilot: `python scripts/hm/download-images.py --limit 20`. Then request representative images with `python scripts/hm/download-images.py --limit 500 --workers 4`. It resumes existing images, handles Kaggle's flattened paths and ZIP-wrapped JPEG responses, and records missing files. Use repeated `--article-id <id>` for an alternative variant from the same mapped Product. The actual 2026-11-06 result is 496 valid images for 496/500 Products; four Products have no available mapped image.
3. Validate: `python scripts/hm/validate-images.py`. Inspect missing/corrupt/duplicate coverage and retry manifest. Do not publish mismatched images.
4. Optimize: `python scripts/hm/optimize-images.py`. Inspect derivative bytes and spot-check visual quality. This does not overwrite originals.
5. Start isolated stack: `docker compose -p recommendation-test -f deploy/docker-compose.recommendation-test.yml up -d recommendation-test-postgres recommendation-test-redis recommendation-api`. Confirm the database name is `recommendation_test`, port 9002 is loopback-only, and no `S3_BUCKET`/`S3_FILE_URL` is configured.
6. Rebind `image-optimized.jsonl` Product/Variant IDs to `data/hm/test-serving/processed/medusa-mapping.jsonl` only after checking all 1,874 SKU mappings against the isolated DB. Save the rebound manifest in the gitignored `data/hm/test-serving/processed/` directory. Import: `docker compose -p recommendation-test -f deploy/docker-compose.recommendation-test.yml exec -T -e HM_IMAGE_ALLOW_LOCAL_MEDIA_WRITE=1 -e HM_IMAGE_INPUT_DIR=/app/data/hm/processed recommendation-api npx medusa exec ./src/scripts/import-hm-images.ts`. The Compose mount exposes optimized binaries read-only; journal and media static directory remain under ignored `data/hm/test-serving/`. A rerun must update zero Products.
7. Verify Store API thumbnail/gallery/URL and Similar Products on multiple Products, then run browser E2E with the test storefront. Check media origin, correct Product identity, Cart/Checkout regression and storage/latency. Fixture results do not replace these real-image gates.
8. Roll back media references if needed: `docker compose -p recommendation-test -f deploy/docker-compose.recommendation-test.yml exec -T -e HM_IMAGE_ALLOW_LOCAL_MEDIA_WRITE=1 -e HM_IMAGE_ROLLBACK=1 recommendation-api npx medusa exec ./src/scripts/rollback-hm-images.ts`. This restores prior Product thumbnail/gallery; uploaded files/File Module records are retained for review and do not delete Products/Orders.

If the test stack is not needed, use `docker compose -p recommendation-test -f deploy/docker-compose.recommendation-test.yml stop recommendation-api recommendation-test-postgres recommendation-test-redis`. Never use `down -v` on project data. The main app remains at ports 8000/9000.
